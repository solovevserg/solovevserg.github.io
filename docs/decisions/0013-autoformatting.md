# Автоформатирование кода

- Статус: принято
- Дата: 2026-04-11

## Контекст

В репозитории нет инструментов автоформатирования: отсутствуют Prettier, ESLint, git-хуки и
lint-staged. Форматирование файлов (`.vue`, `.ts`, `.less`, `.json`) не единообразно и зависит от
настроек редактора конкретного разработчика. Pre-commit хук позволит форматировать только изменённые
файлы перед каждым коммитом, не трогая остальной код.

## Варианты

### Вариант A — Prettier + lint-staged + husky

Стандартная связка для экосистемы Node.js.

**Зависимости (devDependencies):**

```text
prettier
lint-staged
husky
```

**Конфигурация:**

- `.prettierrc` — правила форматирования
- `package.json` → секция `"lint-staged"` — какие файлы и чем форматировать
- `husky init` создаёт `.husky/pre-commit`, вызывающий `npx lint-staged`

**Плюсы:**

- Отраслевой стандарт, хорошая документация
- lint-staged умеет restage отформатированных файлов
- Легко расширить: добавить ESLint, tsc --noEmit и т.д.

**Минусы:**

- +3 devDependency (~300 кБ в node_modules)
- Требует `husky install` после `npm install` (добавляется в `prepare`-скрипт)
- `.husky/` — дополнительная директория в репозитории

---

### Вариант B — Prettier + shell-скрипт pre-commit

Минималистичный вариант без husky и lint-staged.

**Зависимости (devDependencies):**

```text
prettier
```

**Конфигурация:**

- `.prettierrc` — правила форматирования
- `.git/hooks/pre-commit` — shell-скрипт, запускающий `npx prettier --write` на staged-файлах
  и делающий `git add` на них

**Плюсы:**

- Только одна новая зависимость
- Хук — обычный shell-скрипт, понятный без знания husky

**Минусы:**

- `.git/hooks/` не версионируется — каждый разработчик должен установить хук вручную
- Нет автоматической установки при `npm install`
- Сложнее расширять

---

## Предлагаемая конфигурация Prettier

Для Nuxt 3 + Vue + LESS + TypeScript предлагается:

```json
{
    "semi": false,
    "singleQuote": true,
    "trailingComma": "es5",
    "printWidth": 100,
    "tabWidth": 2,
    "vueIndentScriptAndStyle": false
}
```

**Обоснование:**

- `semi: false` — стиль без точек с запятой, характерный для Vue-экосистемы
- `singleQuote: true` — одинарные кавычки, как в большинстве Vue/Nuxt-проектов
- `printWidth: 100` — компромисс между читаемостью и шириной экрана
- `vueIndentScriptAndStyle: false` — `<script>` и `<style>` не имеют дополнительного отступа,
  что снижает общий уровень вложенности в `.vue`-файлах

**Форматируемые расширения:** `.vue`, `.ts`, `.js`, `.json`, `.less`, `.md`

---

## Решение

Принят вариант A (husky + lint-staged). Реализовано:

- установлены `prettier`, `lint-staged`, `husky` в devDependencies
- создан `.prettierrc` с конфигурацией выше
- `package.json`: добавлен `"prepare": "husky"`, `"format": "prettier --write ."` и секция `"lint-staged"`
- `.husky/pre-commit` вызывает `npx lint-staged`

## Последствия

**Положительные:**

- Форматирование применяется автоматически для всех участников проекта после `npm install`
- Только изменённые файлы форматируются при коммите — быстро даже на большой кодовой базе
- Стиль кода унифицирован независимо от настроек редактора

**Отрицательные / риски:**

- При первом коммите после внедрения staged-файлы будут отформатированы — разницу следует
  проверить перед коммитом
