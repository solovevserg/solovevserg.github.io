# Устранение FOUC при переключении темы

* Статус: предложено
* Дата: 2026-03-30

## Контекст и постановка задачи

Текущая реализация темы (`composables/useTheme.ts` + `plugins/theme.client.ts`) работает следующим образом:

1. Сервер генерирует HTML без атрибута `data-theme` на `<html>`
2. CSS применяет тёмную тему по умолчанию через `:root { ... }`
3. После загрузки JS клиент читает `localStorage['theme']` и устанавливает `data-theme`

**Проблема:** если пользователь сохранил светлую тему, при загрузке страницы происходит FOUC (Flash of Unstyled Content):

```
[браузер рендерит HTML] → тёмная тема (~16–50мс) → JS выполняется → светлая тема
                          ↑ видимая вспышка тёмного фона
```

FOUC заметен только пользователям со светлой темой в `localStorage`. Пользователи с тёмной темой (дефолт) его не видят.

## Движущие факторы

- Устранить визуальную вспышку при загрузке страницы
- Сохранить SSG-совместимость (GitHub Pages, статические файлы)
- Минимальное усложнение кодовой базы
- Не вводить новые зависимости (ADR 0006 отклонён)

## Рассмотренные варианты

### Вариант A — Инлайн-скрипт в `<head>` *(выбранный)*

Добавить синхронный `<script>` в `<head>` **до** подключения стилей. Браузер выполняет его немедленно, до первой отрисовки страницы.

```html
<head>
  <script>
    (function() {
      try {
        var t = localStorage.getItem('theme');
        if (!t) t = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
        document.documentElement.dataset.theme = t;
      } catch(e) {}
    })();
  </script>
  <link rel="stylesheet" ...>
</head>
```

В Nuxt 3 добавляется через `app.head.script` в `nuxt.config.ts`:

```typescript
app: {
  head: {
    script: [
      {
        innerHTML: `(function(){try{var t=localStorage.getItem('theme');if(!t)t=window.matchMedia('(prefers-color-scheme:dark)').matches?'dark':'light';document.documentElement.dataset.theme=t}catch(e){}})()`,
        tagPosition: 'head',
      }
    ]
  }
}
```

**Порядок выполнения:**
1. Браузер парсит `<head>`
2. **Выполняет инлайн-скрипт** → `data-theme` установлен
3. Загружает CSS → применяет корректный селектор (`:root` или `:root[data-theme="light"]`)
4. Первая отрисовка уже с правильной темой — FOUC отсутствует

**Размер:** ~150 байт минифицированного JS.

**Плюсы:**
- Полностью устраняет FOUC
- Работает в SSG без сервера
- Не требует новых зависимостей
- Совместим с существующей CSS-архитектурой

**Минусы:**
- Блокирует парсинг HTML на ~1мс (незначительно, скрипт синхронный но крошечный)
- Нужно продублировать логику определения темы (есть в `useTheme.ts`)

---

### Вариант B — CSS `@media (prefers-color-scheme)` без JS

Убрать JS-управление темой полностью. Тема определяется только системными настройками через CSS:

```less
:root { /* тёмная тема */ }
@media (prefers-color-scheme: light) { :root { /* светлая тема */ } }
```

**Плюсы:**
- Нулевой JS, нулевой FOUC
- Мгновенная реакция на смену системной темы

**Минусы:**
- Пользователь **не может выбрать тему** независимо от ОС
- Полностью теряется кнопка переключения в хедере
- Несовместимо с текущим UX

---

### Вариант C — Принять текущее поведение

Оставить как есть. FOUC заметен только на светлой теме, большинство пользователей используют тёмную (дефолт).

**Плюсы:** ничего менять не нужно.

**Минусы:** FOUC существует и ухудшает perceived performance для части пользователей.

---

### Вариант D — `<style>` тег с `visibility: hidden` до инициализации

Скрыть `<body>` до выполнения JS:

```html
<style>html:not([data-theme]) body { visibility: hidden }</style>
```

**Плюсы:** не требует инлайн-скрипта.

**Минусы:** страница остаётся невидимой если JS не загрузится. Ухудшает LCP.

## Принятое решение

**Принят Вариант A** (инлайн-скрипт в `<head>`).

Это стандартный отраслевой подход («anti-FOUC script»), применяемый в том числе в `@nuxtjs/color-mode` и большинстве крупных сайтов. Он прозрачен, минимален и не добавляет зависимостей.

`plugins/theme.client.ts` **сохраняется** — он по-прежнему нужен для синхронизации реактивного состояния `isDark` с DOM и для обработки смены темы через кнопку. Инлайн-скрипт только ускоряет первоначальное применение темы.

### Чек-лист реализации

- [ ] Добавить `app.head.script` с инлайн-скриптом в `nuxt.config.ts`
- [ ] Убедиться что `tagPosition: 'head'` ставит скрипт **до** `<link rel="stylesheet">`
- [ ] Проверить: нет FOUC при первом заходе со светлой темой в localStorage
- [ ] Проверить: нет FOUC при первом заходе без localStorage (системная тема)
- [ ] Проверить: кнопка переключения работает корректно

## Последствия

**Положительные:**
- FOUC устранён для всех пользователей
- Воспринимаемая скорость загрузки улучшается

**Отрицательные / риски:**
- ~1мс дополнительной синхронной блокировки парсинга (практически незаметно)
- Дублирование логики «прочитать localStorage + системная тема» (оригинал в `useTheme.ts`)
- Nuxt может экранировать `innerHTML` скрипта — нужно проверить генерацию HTML
