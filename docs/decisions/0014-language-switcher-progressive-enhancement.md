# Кнопка переключения языка: прогрессивное улучшение через ссылку с перехватом клика

- Статус: принято
- Дата: 2026-04-11

## Контекст

Кнопка переключения языка в `AppHeader.vue` реализована как `<button>` с обработчиком
`@click="setLocale(otherLocale.code)"`. До гидратации (`nuxt generate` → статический HTML)
кнопка визуально присутствует, но полностью неинтерактивна: клик ничего не делает.

Для SSG-сайта это ухудшает воспринимаемую производительность: пользователь, кликнувший по
переключателю до завершения гидратации, не получает никакой реакции. Браузер не может помочь,
потому что `<button>` без `href` не несёт навигационной семантики.

Хочется:

1. **До гидратации** — переключатель работает как обычная ссылка: браузер переходит на
   эквивалентную страницу альтернативной локали.
2. **После гидратации** — клик перехватывается Vue, вызывается `setLocale()` без перезагрузки
   страницы (SPA-переход с сохранением состояния).

## Релевантный контекст проекта

- `@nuxtjs/i18n`, стратегия `prefix_except_default`: RU → `/`, EN → `/en/...`
- Composable `switchLocalePath(code)` возвращает URL текущей страницы в указанной локали
- Composable `setLocale(code)` меняет локаль программно, без перезагрузки

## Варианты

### Вариант A — `<a>` с `@click.prevent` после гидратации (рекомендуется)

Заменить `<button>` на `<a>`, чей `href` указывает на `switchLocalePath(otherLocale.code)`.
После гидратации Vue перехватывает клик через `@click.prevent` и вызывает `setLocale()`.

```vue
<script setup lang="ts">
const switchLocalePath = useSwitchLocalePath()
// ...
const otherLocale = computed(() => locales.value.find((l) => l.code !== locale.value))
const otherLocalePath = computed(() =>
    otherLocale.value ? switchLocalePath(otherLocale.value.code) : '/'
)

function switchLang(e: MouseEvent) {
    if (otherLocale.value) {
        e.preventDefault()
        setLocale(otherLocale.value.code)
    }
}
</script>

<template>
    <a v-if="otherLocale" :href="otherLocalePath" class="ctrl-btn" @click="switchLang">
        {{ otherLocale.code.toUpperCase() }}
    </a>
</template>
```

**Как работает:**

- До гидратации: `<a href="/en/">EN</a>` — браузер выполняет полный переход (работает даже без JS).
- После гидратации: `@click` перехватывает событие, `e.preventDefault()` блокирует навигацию
  браузера, `setLocale()` меняет локаль как SPA.

**Плюсы:**

- Прогрессивное улучшение: кнопка работает на любой стадии загрузки
- Семантически верный HTML: ссылка на альтернативную локаль (`rel="alternate"` можно добавить)
- Логика переключения остаётся простой — не добавляется сложности
- Совместимо с `<hreflang>` и SEO (браузер и краулеры видят реальные URL)

**Минусы:**

- При клике до гидратации происходит полная перезагрузка страницы (приемлемо — лучше, чем ничего)
- Нужно убедиться, что `switchLocalePath` корректно работает на всех страницах (в т.ч. динамических)

### Вариант B — `<NuxtLink>` с `locale` prop

Использовать `<NuxtLink :to="otherLocalePath">` вместо `<a>`.

```vue
<NuxtLink
    v-if="otherLocale"
    :to="otherLocalePath"
    class="ctrl-btn"
    @click.native="setLocale(otherLocale.code)"
>
  {{ otherLocale.code.toUpperCase() }}
</NuxtLink>
```

**Плюсы:**

- Нативная интеграция с Nuxt Router

**Минусы:**

- `@click.native` устарело в Vue 3 — не работает на компонентах; нужен `@click`, но тогда
  `NuxtLink` сам инициирует роутерную навигацию, `setLocale()` вызывается дважды
- `NuxtLink` рендерится как `<a>` только после гидратации; до неё — тоже `<a>`, но без
  Vue-обработчиков, так что поведение до гидратации такое же, как в варианте A
- Сложнее контролировать порядок: `setLocale()` vs роутерный переход

## Неявный стейт: почему `<a>` без дополнительных мер не работает

`@nuxtjs/i18n` по умолчанию включает `detectBrowserLanguage.useCookie: true`. При вызове
`setLocale()` модуль записывает cookie `i18n_redirected`. При инициализации клиентского приложения
на новой вкладке cookie читается и **переопределяет локаль, определённую из URL**. В результате
новая вкладка, открытая по ссылке `/en/`, показывает русский язык, если cookie хранит `'ru'`.

Это делает вариант A нерабочим без явного отключения cookie-детекции.

## Решение

Принять **вариант A** с обязательным дополнением: отключить `detectBrowserLanguage` в
`nuxt.config.ts`.

```ts
i18n: {
    // ...
    detectBrowserLanguage: false,
}
```

При `detectBrowserLanguage: false` i18n не читает cookie при инициализации. Единственный источник
правды — URL. Это разумно для сайта с явным переключателем языка: пользователь сам выбирает
локаль, автодетекция по браузеру не нужна.

В `AppHeader.vue`: `<button>` заменяется на `<a :href="otherLocalePath">`. Клик перехватывается
через `@click="switchLang"`, где modifier-клики (Ctrl/⌘/Shift) пропускаются без перехвата —
браузер открывает новую вкладку по href, и локаль корректно определяется из URL.

```vue
function switchLang(e: MouseEvent) { if (!otherLocale.value) return if (e.ctrlKey || e.metaKey ||
e.shiftKey) return e.preventDefault() setLocale(otherLocale.value.code) }
```

## Последствия

**Положительные:**

- Переключатель работает до гидратации (полный переход) и после (SPA, без перезагрузки)
- Открытие в новой вкладке показывает правильную локаль — URL является единственным источником
  правды
- Семантически корректный HTML; ссылки на альтернативные локали видны краулерам
- Убран скрытый глобальный стейт (cookie), усложнявший предсказуемость поведения

**Отрицательные / риски:**

- При клике до гидратации — полный переход вместо SPA (неизбежный компромисс при SSG)
- Пользователи, впервые заходящие на сайт, всегда видят RU (defaultLocale); автодетекции по
  `Accept-Language` больше нет. Для личного портфолио это приемлемо
- `switchLocalePath` на динамических маршрутах (страницы блога) должен возвращать правильный URL;
  проверено вручную после реализации
