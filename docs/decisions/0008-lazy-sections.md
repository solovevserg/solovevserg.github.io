# Ленивая загрузка секций лендинга после «Обо мне»

* Статус: реализовано
* Дата: 2026-03-30

## Контекст и постановка задачи

Лендинг — SSG, HTML полностью генерируется на этапе сборки. FCP/LCP определяются временем доставки HTML и ресурсов, необходимых для первого рендера (CSS, шрифты, изображение героя). Тем не менее JavaScript-бандл влияет на TTI и косвенно на LCP через гидратацию:

- Nuxt 3 включает весь импортируемый JS в `entry.js` (или связанные чанки), браузер парсит его до первой интерактивности.
- Секции ниже фолда (Опыт, Навыки, Образование, …) несут код Vue-компонентов, который не нужен при первом рендере.

**Цель:** уменьшить объём JS, разбираемого браузером до отрисовки видимой области, что улучшает FCP, LCP и TTI.

## Движущие факторы

- Снизить вес `entry.js` / первичных чанков
- Не нарушать SEO (HTML остаётся в статике, только гидратация откладывается)
- Использовать возможности Nuxt 3 без дополнительных зависимостей

## Рассмотренные варианты

### Вариант A — Префикс `Lazy` в шаблоне страницы *(рекомендуемый)*

Nuxt 3 автоматически создаёт async-версию любого компонента по имени с префиксом `Lazy`:

```vue
<!-- pages/index.vue -->
<SectionHero />
<SectionAbout />

<LazySectionExperience />
<LazySectionSkills />
<LazySectionEducation />
<LazySectionTeaching />
<LazySectionFacts />
<LazySectionContact />
```

Компоненты `Lazy*` разбиваются в отдельные чанки и загружаются по мере появления в DOM (intersection или при старте гидратации).

**Плюсы:**
- Нулевые изменения в компонентах — только шаблон страницы
- Nuxt handles code splitting автоматически
- HTML по-прежнему полностью присутствует в статике (SEO не страдает)

**Минусы:**
- Гидратация секций ниже фолда начнётся чуть позже — незаметно при прокрутке, но теоретически возможен brief layout shift при очень медленном соединении

---

### Вариант B — `defineAsyncComponent` вручную

```typescript
const SectionSkills = defineAsyncComponent(() => import('~/components/sections/SectionSkills.vue'))
```

Аналогично A, но требует явного импорта каждого компонента.

**Плюсы:** явный контроль над каждым чанком.
**Минусы:** бойлерплейт; Nuxt `Lazy`-префикс делает то же самое автоматически.

---

### Вариант C — Отложенный рендер через `v-if` + Intersection Observer

Не рендерить секции в DOM до появления в viewport:

```vue
<SectionSkills v-if="skillsVisible" />
```

**Плюсы:** экономит и JS, и CSS (компонент не гидратируется вообще до scroll).
**Минусы:** нарушает SEO для SSG (элемент отсутствует в HTML при первой загрузке); сложнее реализовать.

---

## Дополнительные способы улучшить FCP / LCP

Помимо code splitting, применимы следующие техники (по убыванию приоритета):

| Техника | Текущий статус | Эффект |
|---|---|---|
| `preload` для LCP-изображения (аватар) | ✅ реализовано | Снижает LCP на 200–500мс |
| `format="avif,webp"` для изображений | ✅ реализовано | Уменьшает трафик изображений на 40–70% |
| Self-hosted шрифты вместо Google Fonts | ❌ не реализовано | Устраняет DNS-lookup + загрузку с внешнего домена (~100мс) |
| Preconnect к fonts.googleapis.com | ❌ не реализовано | Снижает задержку шрифтов на 50–150мс |
| `font-display: swap` | зависит от Google Fonts | Предотвращает блокировку рендера шрифтами |
| Минификация/дедупликация CSS | через Nuxt/Vite | Небольшой эффект |
| Удаление неиспользуемых правил CSS | ❌ не проверялось | Зависит от объёма |
| `<link rel="modulepreload">` для критических чанков | Nuxt настраивает автоматически | — |
| HTTP/2 Push или Early Hints | зависит от хостинга (GitHub Pages не поддерживает) | — |
| Inline critical CSS | сложно с Nuxt SSG | Небольшой эффект для небольшого сайта |

**Наибольший незакрытый потенциал:** self-hosted шрифты — единственное внешнее блокирующее соединение при загрузке.

## Принятое решение

Не принято — требует реализации.

**Рекомендуется Вариант A** как наименее инвазивный: заменить `SectionExperience`, `SectionSkills`, `SectionEducation`, `SectionTeaching`, `SectionFacts`, `SectionContact` на `Lazy`-версии в `pages/index.vue`.

### Чек-лист реализации

- [ ] Добавить `Lazy`-префикс к секциям ниже фолда в `pages/index.vue`
- [ ] Проверить в DevTools: чанки компонентов действительно отделились от `entry.js`
- [ ] Измерить LCP/FCP до и после (Lighthouse, WebPageTest)
- [ ] Убедиться, что HTML в сгенерированном `index.html` не изменился (SEO)
- [ ] Опционально: добавить `preconnect` к `fonts.googleapis.com`

## Последствия

**Положительные:**
- Уменьшение веса первичного JS-бандла
- Ускорение TTI и потенциальное улучшение LCP

**Отрицательные / риски:**
- При очень медленном соединении возможна кратковременная незагидратированность секций при прокрутке
- Нужно контролировать количество чанков (слишком много мелких чанков хуже одного среднего)
