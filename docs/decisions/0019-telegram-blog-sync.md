# 0019. Синхронизация блога с Telegram-каналом

- **Статус:** принято
- **Дата:** 2026-11-01

## Контекст

Посты публикуются в Telegram-канале [@phi_code](https://t.me/phi_code). Нужно, чтобы они
автоматически появлялись в блоге на сайте без ручного копирования: телега — источник
публикации, сайт — зеркало с полными текстами, ссылками на исходные посты и CTA подписки.

## Варианты

1. **Bot API `getUpdates`** — бот-админ канала, джоба по расписанию забирает `channel_post`
   и `edited_channel_post`. Плюсы: точное форматирование (entities), фото в полном размере,
   ноль сторонних зависимостей. Минусы: окно апдейтов 24 часа (компенсируется поллингом
   каждые 12 часов), нет доступа к истории старше окна.
2. **MTProto (gramjs/telethon)** — полный доступ к истории по юзер-сессии. Отклонён: для CI
   нужна интерактивная регистрация сессии, api_id/api_hash и лишний вектор отзыва доступа.
3. **Парсинг t.me/s/<канал>** — без секретов, но неофициальная вёрстка может измениться,
   фото в пониженном качестве. Отклонён по надёжности.

## Решение

Вариант 1. Расписание джобы — `0 6,18 * * *` UTC (каждые 12 часов, внутри 24-часового окна).

- Скрипт: `scripts/sync-telegram.mjs` (Node 20+, зависимость — только richtypo
  для типографики), запуск в CI — `.github/workflows/sync-blog.yml`, локально —
  `npm run blog:sync` (токен из `.env`).
- Апдейты подтверждаются смещением `offset` только **после** успешной обработки;
  состояние — в коммитируемом файле `.telegram-sync-state.json`. Повторная обработка
  безопасна: посты сопоставляются по `telegram_message_id` из фронтматтера.
- Сырые апдейты дополнительно кэшируются в `.telegram-sync-cache.json` (в git не
  коммитится) ДО обработки; джоба сохраняет его через `actions/cache` (TTL 30 дней,
  префикс ключа `tg-updates-`) даже при падении — упавший скрипт можно чинить и
  перезапускать без потери постов, если Telegram уже подтвердил апдейты.
- Правки постов (`edited_channel_post`) обновляют существующий файл: slug и дата
  сохраняются, добавляется `updated_at`. Правка ещё не синхронизированного поста создаёт его.
- Посты в блог **могут добавляться и не из Telegram**: md-файлы в `content/ru/blog/` без
  `telegram_message_id` (или вообще без привязки к телеге) ведутся вручную — синк их
  не трогает и не удаляет.
- Slug: `YYYY-MM-DD-<транслитерированный заголовок>`; заголовок — первое предложение поста
  (включая `!` и `?`).
- Фото скачиваются в `public/images/blog/<message_id>/`; альбомы группируются по
  `media_group_id`. При правке альбома фотографии берутся из уже скачанных (в окно
  `getUpdates` приходят не все части альбома).

## Последствия

- История канала старше 24 часов недоступна через Bot API: посты, опубликованные до
  подключения бота, попадают в блог после любой их правки (или ручного переноса md-файла).
- Токен бота хранится в GitHub Secrets (`TG_BOT_TOKEN`) и локально в `.env` (в `.gitignore`).
- Синк коммитит в `master` от имени `telegram-sync-bot`, что запускает штатный деплой
  (`deploy.yml`). Пустой прогон не создаёт коммит.
- Нематериальные вложения (видео, опросы, стикеры) пропускаются с предупреждением; текст
  поста (caption) сохраняется.
