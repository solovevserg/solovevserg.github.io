# Кинематографичный редизайн: «Рубрикация»

- Статус: реализовано
- Дата: 2026-07-16

## Контекст и постановка задачи

Прежний дизайн был технически исправным, но визуально неотличим от типового
портфолио разработчика: тёмный фон, индиговый акцент `#6366f1`, сетка карточек
со скруглением 10px, hover-подъём на 2px. Такой макет не удерживает внимание и
ничего не сообщает о человеке за ним.

Требовался принципиально новый дизайн уровня awwwards: смелая типографика,
выраженная моторика, необычные переходы, кинематографичность.

Ключевое наблюдение: у владельца сайта редкое сочетание ролей — ведущий
разработчик, аспирант философии науки (тема диссертации — представление знаний
в структуре **искусственных языков**), преподаватель и спикер с докладами вроде
«От латыни до async/await: археологические раскопки JavaScript». Дизайн должен
опираться на это, а не на общие места «тёмная тема + акцент».

## Движущие факторы

- Визуальная смелость и запоминаемость — главный критерий задачи
- Концепция должна следовать из биографии, а не быть декором поверх неё
- Сохранить SSG, две темы, i18n, семантику и доступность (ADR 0001, 0007, 0016)
- Не вводить зависимостей: GSAP/Lenis/Framer тянут килобайты и риск на статике
- Контент обязан читаться без JS и при `prefers-reduced-motion`

## Концепция

**«Рубрикация»** — сайт как манускрипт формального языка.

Рубрикация — средневековая практика выделять инициалы и пометки на полях
красной киноварью. Отсюда вся система:

- **Палитра**: обсидиан (фон) · кость (текст) · вермильон (рубрика). Один
  акцент, никаких вторичных цветов. В светлой теме обсидиан и кость меняются
  местами: пергамент и тушь.
- **Маргиналии**: номера глав 01…07 на левом поле (`ChapterRail`), рубричные
  номера у заголовков, моноширинные пометки.
- **Инициал**: первая буква биографии — вермильоновая буквица (`::first-letter`).
- **Плёнка**: зерно и виньетка поверх всей страницы дают кадру фактуру.
- **Типографика**: Inter 900 в верхнем регистре, трекинг −0.045em, обводные
  строки. Скругления убраны (`--radius: 0`) — редакционная строгость.

## Рассмотренные варианты

### Вариант A — Косметика поверх текущего макета

Сменить акцент, увеличить кегль, добавить hover-эффекты.

**Плюсы:** дёшево, нулевой риск регрессий.
**Минусы:** не решает задачу — «принципиально новый» дизайн не получается
перекраской. Отклонён.

### Вариант B — Библиотека анимаций (GSAP + Lenis + ScrollTrigger)

Индустриальный стандарт awwwards-сайтов.

**Плюсы:** ScrollTrigger решает pin/scrub из коробки; предсказуемое поведение.
**Минусы:** ~70 КБ JS сверху на статический сайт из семи секций; Lenis
перехватывает нативный скролл (на Windows с колесом ощущается инородно);
лицензия GSAP. Отклонён: всё нужное закрывается ~120 строками своих
композаблов.

### Вариант C — Собственная моторика на IntersectionObserver + rAF _(выбран)_

- `v-reveal` — одна общая IO на все проявления
- `SplitText` — пословный подъём из-под маски
- Липкий стек карточек опыта — чистый CSS `position: sticky`
- Горизонтальная лента навыков — sticky + перевод вертикального прогресса
  в `translateX`
- Параллакс hero — `--p` пишется прямо в CSS-переменную, минуя реактивность

**Плюсы:** ноль зависимостей, нативный скролл, полный контроль над деградацией.
**Минусы:** граничные случаи (замеры, ресайз, порядок гидратации) приходится
закрывать самому — что и сделано ниже.

## Принятое решение

Принят **Вариант C**.

### Ключевые технические решения

**Ворота анимаций (`useMotionGate`).** Пока играет интро-шторка, элементы под
ней уже пересекают вьюпорт: IO сработал бы вхолостую, и к подъёму шторки первый
экран оказался бы уже проявленным. Ворота придерживают выдачу `is-in` и
проявляют накопленную очередь по окончании первого занавеса.

**Стартовое состояние — только под `html.has-js`.** Класс вешает инлайн-скрипт
до первой отрисовки (по схеме ADR 0007). Без JS `.reveal` не имеет скрытого
состояния и контент рендерится статично и целиком.

**`getSSRProps` у `v-reveal`.** Класс `reveal` проставляется уже на сервере:
иначе статический HTML отрисуется видимым, а гидратация спрячет содержимое —
на первом экране это заметная вспышка.

**Интро — CSS, а не таймеры.** Таймлайн шторки задан анимациями; JS только
снимает класс, пишет флаг сеанса и открывает ворота. Если бандл не выполнится,
шторка уедет сама. Завершение ловится через `Animation.finished`, а не
`animationend`: промис разрешается и для уже завершённых анимаций, поэтому
поздняя гидратация не может «проспать» событие.

**Фасад вместо iframe YouTube.** Плеер тянет около мегабайта на каждый заход,
хотя большинство читателей до докладов не доскроллит. Грузится кадр, плеер —
по клику, сразу с autoplay.

**Тема работы вынесена в текст.** Прежде она пряталась в тултип с отдельным
bottom sheet для мобильных. У этих работ содержание — сильная часть биографии;
показываем цитатой и удаляем две ветки кода.

### Границы деградации

| Условие                  | Поведение                                                                               |
| ------------------------ | --------------------------------------------------------------------------------------- |
| Нет JS                   | Контент виден целиком, без проявлений; интро уезжает по CSS                             |
| `prefers-reduced-motion` | Интро не запускается, проявления мгновенны, зерно и ленты статичны                      |
| Тач / грубый указатель   | Кастомный курсор и магнит не монтируются                                                |
| Ниже `@bp-md`            | Лента навыков — обычная сетка и мобильный скролл, без закрепления                       |
| Ниже `@bp-md`            | Стек опыта переходит в обычный поток: закреплённая карточка выше экрана не дочитывается |

## Последствия

**Положительные:**

- Дизайн опирается на биографию: концепция читается, а не декорирует
- Ноль новых зависимостей, нативный скролл сохранён
- Убраны тултип темы работы и мобильный bottom sheet — минус две ветки кода
- Плеер YouTube больше не грузится на каждый заход
- Реализованы варианты A и B из ADR 0015 (инлайн-фон + отказ от wildcard
  `transition`), см. обновлённый статус там

**Отрицательные / риски:**

- `--bg` продублирован в инлайн-стиле `nuxt.config.ts` — при смене палитры
  править обе точки
- Брейкпоинты продублированы в `composables/useBreakpoint.ts` для JS-логики
- Липкий стек требует, чтобы карточка была ниже вьюпорта: при росте числа
  пунктов в карточке опыта её низ перестанет дочитываться на десктопе
- Ленту навыков нужно перемерять на ресайз; замер завязан на `.container`
  внутри секции

## Найденное при визуальной проверке

Сборка проверялась скриншотами через CDP (Chrome headless) на 390/768/1600px
в обеих темах. Дефекты, которые не видны в разметке:

1. **`:global(html.intro) .intro` в scoped-стилях** Vue схлопывает до
   `html.intro` — правило садилось на сам `<html>`, делая его `position: fixed;
pointer-events: none`. Страница на время интро не прокручивалась. Решение:
   шторка вынесена в не-scoped блок с собственным префиксом классов.
2. **Заливка строк контактов** уезжала на 101% вниз без `overflow: hidden` и
   ложилась на соседнюю строку — четыре из пяти строк были залиты красным.
3. **`.mobile-scroll-list` вне `.container`** (лента навыков) отрицательными
   полями растягивал документ на `--gutter` вправо, а с ним и fixed-шапку.
4. **Пословные маски**: при плотном интерлиньяже display-заголовков глифы
   выходят за свой line-box, и на `translateY(110%)` верхушки букв
   непроявленного заголовка видны из-под маски. Сдвиг увеличен до 150%.
5. **Подписи глав на рельсе** не помещались между краем окна и колонкой текста
   и наезжали на контент — заменены на штрих, подпись осталась под курсором.
