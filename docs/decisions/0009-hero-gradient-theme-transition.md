# Плавный переход градиента героя при смене темы

- Статус: отклонено (в пользу варианта с CSS-маской)
- Дата: 2026-03-30

## Контекст и постановка задачи

Секция `SectionHero` накладывает градиентный оверлей на фотографию:

```less
&__photo-grad {
    background:
        radial-gradient(ellipse 75% 88% at 62% 46%, transparent 30%, var(--bg) 72%),
        linear-gradient(to right, var(--bg) 0%, transparent 28%);
}
```

`var(--bg)` меняется при переключении темы (`#0c0c0e` ↔ `#f5f5f3`). В `global.less` задан глобальный переход:

```less
html {
    transition:
        background 0.3s,
        color 0.3s;
}
```

**Проблема:** CSS-переходы не работают на `background` с `radial-gradient()` / `linear-gradient()`, потому что браузер не умеет интерполировать градиенты, содержащие CSS-переменные. Результат — градиент щёлкает мгновенно (белый → чёрный или наоборот), пока остальной фон плавно переходит.

## Движущие факторы

- Визуальная согласованность: все остальные элементы переключаются плавно
- Сохранить SSG-совместимость и отсутствие FOUC
- Не усложнять код компонента сверх необходимого

## Рассмотренные варианты

### Вариант A — Два оверлея с переключением `opacity` _(рекомендуемый)_

Создать два отдельных элемента: один с тёмным градиентом, другой со светлым. Переключать `opacity` между ними — CSS отлично анимирует `opacity`.

```html
<div class="hero__photo-grad hero__photo-grad--dark" />
<div class="hero__photo-grad hero__photo-grad--light" />
```

```less
.hero__photo-grad {
    position: absolute;
    inset: 0;
    pointer-events: none;
    transition: opacity 0.3s ease;

    &--dark {
        background:
            radial-gradient(ellipse 75% 88% at 62% 46%, transparent 30%, #0c0c0e 72%),
            linear-gradient(to right, #0c0c0e 0%, transparent 28%);
        opacity: 1;
    }

    &--light {
        background:
            radial-gradient(ellipse 75% 88% at 62% 46%, transparent 30%, #f5f5f3 72%),
            linear-gradient(to right, #f5f5f3 0%, transparent 28%);
        opacity: 0;
    }
}
```

```less
// В unscoped-блоке (управление через data-theme):
html[data-theme='light'] {
    .hero__photo-grad--dark {
        opacity: 0;
    }
    .hero__photo-grad--light {
        opacity: 1;
    }
}
```

**Плюсы:**

- CSS-only, без JS
- `opacity` анимируется плавно браузером всегда
- Работает синхронно с остальными переходами темы
- Цвета хардкодятся один раз — значения совпадают с переменными в `global.less`

**Минусы:**

- Цвета фона (`#0c0c0e`, `#f5f5f3`) дублируются в компоненте; при изменении палитры нужно обновить оба места
- Два DOM-элемента вместо одного (незначительно)

---

### Вариант B — CSS `@property` (Houdini)

Зарегистрировать CSS-переменную как `<color>`, тогда браузер сможет интерполировать её значение:

```css
@property --bg-val {
    syntax: '<color>';
    inherits: true;
    initial-value: #0c0c0e;
}

html[data-theme='light'] {
    --bg-val: #f5f5f3;
}
html {
    transition: --bg-val 0.3s;
}
```

Затем использовать `--bg-val` вместо `var(--bg)` в градиентах.

**Плюсы:** элегантно, один оверлей, переменная интерполируется нативно.
**Минусы:** Safari 15 и ниже не поддерживает `@property`; переходы по `@property` поддерживаются только Chrome 117+ / Safari 17.2+ (2024). Для части пользователей по-прежнему будет рывок.

---

### Вариант C — JS-анимация через `requestAnimationFrame`

При клике на кнопку темы вручную интерполировать цвет фона в градиенте через JS.

**Плюсы:** полный контроль над анимацией.
**Минусы:** сложно, требует парсинга цветов, может конфликтовать с CSS-переходами. Избыточно.

---

### Вариант D — Принять текущее поведение

Рывок градиента незначителен на фоне плавного перехода остальных элементов.

**Плюсы:** ничего делать не нужно.
**Минусы:** заметный визуальный артефакт при переключении темы именно в героне (самом заметном блоке страницы).

---

## Принятое решение

Не принято — требует реализации.

**Рекомендуется Вариант A** как надёжный и поддерживаемый во всех браузерах. Вариант B следует переоценить через 1–2 года по мере роста поддержки `@property`.

### Чек-лист реализации

- [ ] Заменить один `hero__photo-grad` на два в шаблоне `SectionHero.vue`
- [ ] Прописать хардкодные цвета тёмной и светлой темы в градиентах
- [ ] Добавить `transition: opacity 0.3s ease` обоим оверлеям
- [ ] Добавить unscoped-блок `<style lang="less">` с переключением `opacity` по `html[data-theme="light"]`
- [ ] Убедиться что длительность совпадает с `transition: background 0.3s` из `global.less`
- [ ] Проверить на всех трёх breakpoint-вариантах (desktop, tablet, mobile)

## Последствия

**Положительные:**

- Плавная и единообразная смена темы по всей странице
- Лучший perceived quality

**Отрицательные / риски:**

- При изменении цветов темы в `global.less` нужно не забыть обновить хардкодные значения в `SectionHero.vue` — риск рассинхронизации. Митигируется комментарием с явной ссылкой на переменные.
